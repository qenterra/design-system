# Unspool migration brief

## Baseline

Unspool is the component and workflow discipline donor. Its operational flow is strong; current screenshot evidence, responsive navigation, field validation, accessibility construction, and issue placement need repair.

## Ordered slices

1. Map current AppPalette/AppTypography/AppMotion roles to generated family semantics.
2. Make the rail responsive: compact under pressure, labeled when space or user choice permits.
3. Reflow search, categories, presets, and filters so critical filters never hide in invisible horizontal scrolling.
4. Add pristine/editing/invalid field state and delay setup errors until interaction.
5. Replace Settings Row APIs so label and control are one accessible unit.
6. Implement typed issue scope: field, row, section, banner, blocking alert.
7. Confirm interrupted-session discard and provide recovery on failed history items.
8. Complete String Catalog, plurals, locale-aware dates/sizes, and terminology.
9. Rebuild current synthetic screenshot evidence across appearance, width, and failure states.

## Acceptance

- Main Browse flow remains continuous and filename-first.
- Preflight and conflict safety remain unchanged or stronger.
- Minimum width exposes all critical filters and actions.
- All toggles and icon buttons have accessible names.
- Multiple scoped issues cannot overwrite one global string.
- Keyboard multi-selection, Quick Look, Finder, long Unicode names, network/disk/conflict/relaunch, VoiceOver, and real Telegram remain explicit live gates.

## Product-specific boundaries

Telegram chat sources, scan range, sender filters, attachment taxonomy, original filename contract, queue, and Skip/Replace/Save a Copy remain Unspool-owned.
