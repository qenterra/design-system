# Cadence migration brief

## Baseline

Cadence is the visual foundation donor. Its adaptive palette and content hierarchy are strong, while token ownership, interaction states, localization, and screenshot fidelity are fragmented.

## Blocking trust work

Smart Collections must become durable or stop promising `Save`. This precedes visual migration because the component language must not legitimize a false outcome.

## Ordered slices

1. Adopt generated semantic color/motion/type adapters without changing product geometry.
2. Fix screenshot root to apply the production appearance/tint and capture the required matrix.
3. Make the new-install rail expanded, give every destination a unique symbol, and preserve user state.
4. Replace local hover/focus booleans with the shared Interactive Row state model.
5. Move user-facing strings to String Catalog with typed/generated keys.
6. Normalize buttons, fields, settings groups, overlays, errors, and empty states.
7. Map Import, Trash, and recovery flows to shared operation patterns.
8. Add playback-first actions to Album and Artist surfaces without importing utility layouts.

## Acceptance

- No raw duplicate family colors/durations/radii in migrated surfaces.
- System/Light/Dark and Increased Contrast preserve hierarchy.
- Minimum/wide screenshots use production fixtures and tint.
- Keyboard focus and selection remain separate.
- Import Review does not clip at minimum width.
- Localization expansion, VoiceOver, Reduced Motion/Transparency, drag/drop, queue, and live playback gaps are reported separately.

## Product-specific boundaries

Persistent player, artwork haze, transport, audio path, lyrics, metadata, playback queue, and music browsing remain Cadence-owned components.
