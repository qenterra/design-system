# Native component snapshots

Run `swift test --filter QenTerraComponentSnapshotTests --disable-sandbox` from the repository root or public package. A missing reference, different dimensions, or any RGBA channel difference greater than 3/255 fails. The complete verification gate always uses locked references.

To intentionally update references, run `QDS_RECORD_SNAPSHOTS=1 swift test --filter QenTerraComponentSnapshotTests --disable-sandbox` once. Inspect every changed PNG at its original size, then run both package test suites without the recording variable and confirm the PNGs were not rewritten.

Snapshots use an offscreen `NSHostingView`, a fixed 1× output pixel canvas, sRGB RGBA normalization, English POSIX locale, UTC, fixed content, and frozen native layer timing after the initial display pass. This lets native symbol layers materialize before their clocks stop. The output canvas does not normalize the native window's backing scale or its glyph rasterization. Accessibility fixtures supply the public `DesignNativeEnvironment` values; they do not change the machine's accessibility settings. They use the installed macOS system fonts and SF Symbols. Run on the same macOS/Xcode rendering environment when comparing references; an intentional OS rendering change requires visual review, not a larger tolerance.

An explicit `designNativeEnvironment` value takes precedence over inherited native accessibility inputs. Without one, components resolve live SwiftUI inputs, with or without `.designSystem(...)`. Configuration supplies profile/density defaults; nearer explicit profile/density keys override those fields. Tests cover opposing accessibility values through the same resolver used by the public environment getter, plus hosted normal/reduced rendering, per-component contrast, standalone behavior, and live configuration changes. SwiftUI's read-only accessibility keys are not injected or swizzled: setting an AppKit High Contrast appearance did not report Increased Contrast to SwiftUI on the recorded host, so that experiment is not evidence of changing native accessibility preferences.

For restricted local environments, SwiftPM supports `--cache-path`, `--config-path`, and `--security-path` pointing at writable task-local directories. The complete verifier creates these alongside its scratch builds. Earlier successful captures emitted warnings about unavailable user cache/configuration/security directories and a read-only manifest-cache database; those warnings did not invalidate the recorded test results.

The test host explicitly sets active-control presentation and the standard blue accent. Its offscreen window is not key or main and the test application stays inactive; no system preference is changed. Spinner visibility is compared with the same unstyled native indicator on a matching appearance and surface, rather than treating this offscreen capture as an active-window accessibility contrast audit.

Each native backing-scale profile contains 47 PNGs covering artwork, media collections, playback, queue, lyrics, metadata, native tables, and Light/Dark controls and all row states, standard/long-copy Settings, compact/expanded navigation, content/operation feedback, two configurable About pages, reduced effects, and live System appearance switching. Three fixed-time gradient boundary PNGs belong to a separate raster profile because their pure image producer has no native window. Reduced Motion uses the shipped static ellipsis. The core surfaces are already opaque, so Reduced Transparency is checked against the same pixels and geometry with transparency reduction disabled.

Native references are selected by the actual OS major version, CPU architecture, and captured window backing scale, for example `macos-27-arm64-backing-1x/` or `macos-27-arm64-backing-2x/`. Capture checks the actual host window before and after rendering and requires a stable scale of 1× or 2×. Pure image references use `macos-27-arm64-raster/` without claiming a native backing scale. There is no fallback across OS, architecture, backing scale, capture origin, or legacy directories, and no automatic skip. Missing or unsupported profiles fail. Each required profile must be captured on its actual rendering environment, visually reviewed at original size, and delivered with the public package before comparison can pass. A 1× host, renamed directory, or injected display scale is not evidence of a 2× native capture.

The verification workflow offers a manual `record_snapshots` diagnostic input for native macOS 26 capture. Before recording, it moves the exact potential typed macOS 26 native 1×, native 2×, and raster directories into recoverable runner-temporary preimages. It exports only one freshly produced native profile containing 47 PNGs and the fresh raster profile containing three PNGs; missing or ambiguous native captures and missing raster captures fail. Stale committed profiles and legacy directories are never exported as fresh evidence. The artifact includes the selected capture profiles, source commit, OS/build, architecture, Xcode, Swift, SDK and runner image metadata, plus a separately labeled post-capture window/screen environment probe whose window scale must match the native profile. This diagnostic capture does not approve references: actual macOS 26 provider capture, genuine native 2× capture where required, and original-size visual review remain separate evidence. The ordinary verification job still compares locked references and is never satisfied by recording new ones.

The fixtures exercise the shipped shared components. The Cadence About fixture supplies synthetic product metadata and an SF Symbol icon; it is not evidence of visual equivalence with the Cadence application. Keyboard interaction, animation in motion, VoiceOver, and consumer acceptance require separate checks.
